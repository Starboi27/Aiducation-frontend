# 아이디(이메일) 찾기 개선 설계서 (2단계 검증 및 동명이인 대응)

> **상태:** 초안 (Draft)
> **작성일:** 2026-05-06
> **대상:** 아이디 찾기 프로세스 및 UI/UX

## 1. 개요
동명이인이 존재할 경우를 대비하여 1단계에서 이름으로 마스킹된 이메일 목록을 조회하고, 2단계에서 사용자가 자신의 이메일을 선택하여 최종 확인(또는 발송) 절차를 진행하는 2단계 프로세스로 개선합니다.

## 2. 사용자 시나리오 (Flow)
1. **[단계 1: 이름 입력]** 사용자가 '이메일 찾기' 화면에서 이름을 입력합니다.
2. **[단계 2: 이메일 목록 조회]** `/api/v1/auth/find-id`를 호출하여 마스킹된 이메일 목록을 가져옵니다.
3. **[단계 3: 이메일 선택]** 화면에 표시된 목록 중 본인의 계정(마스킹된 이메일)을 클릭합니다.
4. **[단계 4: 최종 확인/발송]** 선택한 이메일 정보를 바탕으로 `/api/v1/auth/send-find-id`를 호출하여 절차를 완료합니다.
5. **[단계 5: 종료]** 결과 메시지를 확인하고 '로그인' 페이지로 이동합니다.

## 3. 기술적 상세 설계 (API 규격)

### 3.1 [Step 1] 이메일 목록 조회
이름을 통해 해당 사용자의 마스킹된 이메일 리스트를 가져옵니다.

- **Endpoint:** `POST /api/v1/auth/find-id`
- **Request Body:**
```json
{
  "name": "이름"
}
```
- **Response Example:**
```json
{
  "success": true,
  "results": [
    { "email": "geg***@naver.com" },
    { "email": "ho***@test.com" }
  ]
}
```

### 3.2 [Step 2] 선택 이메일 처리/발송
목록에서 선택된 특정 이메일 정보를 서버로 전달합니다.

- **Endpoint:** `POST /api/v1/auth/send-find-id`
- **Request Body:**
```json
{
  "userId": "gegulee22@naver.com" 
}
```
*(참고: API 파라미터명이 `userId`이나 실제로는 선택한 '이메일 주소'를 전달합니다.)*

## 4. 프론트엔드 변경점

### 4.1 상태 관리 (State)
- `findIdStep`: `'input'`(이름 입력) | `'list'`(이메일 선택) | `'complete'`(완료) 단계 구분.
- `foundEmails`: 1단계 결과로 받은 이메일 목록 저장.
- `selectedEmail`: 사용자가 목록에서 클릭한 이메일 저장.

### 4.2 UI 구성
- **[조회 화면]** 이름 입력 Input + [찾기] 버튼.
- **[목록 화면]** "본인의 이메일을 선택해주세요" 문구와 함께 이메일 리스트 버튼들. 클릭 시 2단계 API 호출.
- **[완료 화면]** "이메일 정보가 확인되었습니다(또는 발송되었습니다)" 안내 및 [로그인 페이지로] 버튼.

## 5. 보안 및 예외 처리
- **마스킹 정책:** 1단계 목록 조회 시 개인정보 보호를 위해 마스킹된 데이터만 노출합니다.
- **정확한 전달:** 2단계 호출 시에는 사용자가 선택한 정확한 값을 서버로 전달하도록 처리합니다.
